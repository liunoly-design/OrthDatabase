# 骨科集采价格治理

通过仓库的采集 Worker 生成候选，经运营 Web 复核发布，最后从独立应用 API 验证。数据口径见 [发布契约](../../../contracts/price-v1.md)，启动及真实样本命令见 [README](../../../README.md)。

## 准备一条候选

1. 从官方执行公告找到正式中选原表。记录公告标题、发文方、公告与附件 HTTPS URL、原始字节 SHA-256、工作表及明细行。核对正式结果与拟中选、限价、采购量附表的区别。如下载到的是预览页、空文件或换版文件，记录失败原因并重新定位来源。
2. 从适用公告核对轮次、执行地区、起日和服务费口径。当前可执行的解析器识别 GH-HD2024-1 产品系统类别结果表，从 B、E、G 列读取产品系统类别、申报企业和金额，并保留表头和原始明细行。对官方公告内嵌的同型结果表，使用 `attachment_format: "html"`，记录原始表元素字节的 SHA-256，行号从表头所在的第 1 行计算。地方执行引用国家价格时，执行通知记在 `notice_url`，国家价格原表记在 `attachment_url`，地方资格附件可填 `local_award_reference`，包括文件页码、表中序号、SHA-256、对应企业与产品系统类别。复核人员可从候选打开对应页确认。用 `YYYY-MM-DD` 或 `null` 记录执行起日。附表和正文证据冲突时交给运营核实口径。
3. 在 `governance.category_composition` 中登记官方文件明确的类别组成。每组填写 `product_system`、包含名称/数量/单位的 `members` 和 `evidence`。按真实披露填写 `note` 说明配件及报价口径。证据填写标题和 HTTPS URL，加 HTML 章节、PDF 文件页码（从 1 开始）或 Excel 工作表、行号和单元格。Excel 证据附原始字节 SHA-256。
4. 如可取得同轮次官方供应清单，在 `supply` 中填公告 URL、清单 URL、标题、原始字节 SHA-256 和拟核验的 `system_code`。Worker 从 `系统表` 核对中选标记、企业、类别和金额，再提取该系统的部件行、平台系统与部件编号及当前、旧版注册证号。把关联范围限定为这个系统，保留配件和中选状态，核对同价是否另有其他系统。只有原始价格证据明确计价到具体品规或套件时，才能建立相应的计价对象。
5. 在 `governance.unresolved` 写明未披露及仍待核实的字段。证号、医保耗材代码、UDI-DI 和平台编号各按各自的证据记录。补充清单里的一项注册证号只关联到证据所指部件。医保码、UDI-DI 及包装关联须有明确的同品规和包装依据。部件价格需要独立的计价口径和来源。其他表型、扫描 PDF 或不能交叉验证的标识，记录出处并交运营复查。

## 交接、复核与查价

使用 [样本清单](../../../samples/hunan-joint-governance.json) 的字段运行 `npm run start:worker -- <manifest.json> <中选原表.xls|.html> [供应清单.xlsx]`。提供 `supply` 时传入两个原始工作簿。Worker 按哈希留档工作簿或官方内嵌结果表，并记录任务 ID、解析器版本和 Skill 版本。把任务 ID、候选编码、待核实项和冲突原因交运营。常规导入输出的 `price_id` 同时是候选编码。有变更请求时按 `candidate_id` 打开复核页。

运营在原表和补充证据之间核对金额、计价单位、执行范围、套件层级、标识关联及待核实项，使用原有的「确认复核」「发布价格」。在发布前从应用 API 验证新价格不可见。发布后按 `price_id` 查询 `/api/v1/prices/{price_id}` 和其 `/evidence`，核对契约版本、价格字段、原表哈希、位置及新版本。已有价格的待审变更只在运营端显示。

## 重跑与更正

- **同一输入重跑**。保留原公告与附件 URL、文件哈希、明细位置，复用价格编码。以采集任务区分运行记录。
- **追加证据**。先用应用 API 读当前 `record_version`，确认价格、主体、适用范围、生效时间与计价口径完全一致。增加新的官方原表位置或补充材料出处。在清单里填 `change.operation: "additional_evidence"`、`target_price_id`、`target_record_version`、`reason`。复核发布沿用价格编码并增加版本。
- **金额冲突**。采集任务保存两边金额、原候选编码和两份来源坐标。从任务页比对原表和执行口径，查证后选择适用的变更类型。
- **官方更正**。依据可定位的官方变更，将 `change.operation` 设为 `"official_correction"`，填目标编码、当前版本和理由。复核发布生成新价，双方通过 `supersedes_price_id` 和 `superseded_by_price_id` 相连。原价格编码仍能查到原先发布的事实。
- **平台误录纠错**。根据同一原表位置重建正确候选，将操作设为 `"platform_correction"` 并记录误录内容和依据。发布更新同一编码的当前快照，旧快照留在版本历史。如果需要更正组成或标识，提交纠正后的完整治理证据包。需要撤销原证据时可以提交只含待核实说明的包。省略整个治理证据包时沿用已发布关联。纠错改变证据适用范围时，须提交重新核对的替换或撤销包。新任务基于当前版本重建后须重新复核。

解析或复核规则改变时更新 Skill 与解析器版本标识。正式材料用生产信源；用来演练冲突和更正的副本只在隔离测试库中使用。

证据与变更理由会进入公开版本历史。用可公开的出处和事实描述变更。
